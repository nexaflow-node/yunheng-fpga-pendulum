# J280 项目全程踩坑清单（2026-10-11 → 10-30）

按"代价"排序。每条都写明**发生了什么、代价、固化的教训**。

---

## A. 模型与仿真（最贵的一类，因为它让所有后续判断都失真）

**A1. 离线模型与 RTL 不同构**
旧 model 的 KQ=[112,107,2253,274]、BD 非零、带双积分；RTL 实际是 KQ=[538,315,4690,450]、
BD 全零、无积分。用旧模型做的所有参数推断全部无效。
→ **教训**：仿真参数必须从 RTL 源文件直接解析（`parity` 做法），不能手抄。

**A2. 极点符号算反**
LQR 给的是 u=−Kx 的 K（负值），RTL 用 u=+K_pos·x。用 A−B·K 算会得到"假不稳定 z=1.18"，
一度让我们以为设计本身有错。
→ **教训**：稳定极点必须用 **A+B·K_pos** 算。

**A3. 仿真对增益没有区分度**
48 组真实捕获态喂进仿真，四种增益变体全部 12/12 存活；仿真预测的最优增益
（K1=280/K3=520）实测并不优。
→ **教训**：仿真能验符号、稳定性、频带结构；**不能用它排增益**。

**A4. 仿真没有机械模态**
仿真里没有 10–13 Hz 的机械峰，所以任何"提高增益"的仿真都低估了抖动。
0A9（KQ_2=5500）仿真说最好、实测全部捕获失败，就是这一条。
→ **教训**：涉及高频/增益的改动，仿真只能当排除法，必须上板。

## B. 方法论：单跑不可信（今天被推翻三次）

**B1. 0D0 的 18.1° 是运气**
同一固件两跑：臂峰峰 18.1° 与 36.1°。基于第一跑得出的"关重锚大胜"结论被第二跑推翻。
**B2. 0E0 的两跑**：48.5° 与 23.8°，同固件、间隔 25 分钟。
**B3. 0B4 的两跑**：31.5° 与 27.8°（这一对还算接近）。
→ **教训**：任何版本至少 2 跑，最好 4 跑；比较用**中位数 + 离散范围**，不看单跑极值。
我们至少有 3 次因为单跑下错结论、多做了一整轮实验。

## C. 数据口径（今天连踩两次，都很隐蔽）

**C1. trace 是 62.5 Hz 抽稀的块末快照**
用它的统计去定 1 ms 实时判据的阈值，误差 10 倍：θ>3.5° 在 trace 上占 4.3%，
在实时信号上占 **49%**（0J0 的高增益因此常开）。
→ **教训**：**实时判据的阈值必须用同口径信号（1 ms 或观测器状态）统计**。

**C2. `arm_speed_deg_s` 是观测器 xc1，不是 va_w**
va_w 是 8 ms 窗口测速，量化噪声 42°/s 一档；用它做突滑判据导致检测器 **98.3% 常开**（0H0）。
→ **教训**：看 trace 列名要回溯到 RTL 里到底是哪个信号。

**C3. 上位机的分项电压列用的是硬编码 K**
0E0 的 capture.json 里 K 还是 [538,315,4690,450]，导致 `feedback_identity_ok=false`，
理论上应该可信的分项全错。
→ **教训**：**每出新固件，同步改 host 5 个 .m 的 K 与零点**；并用
`feedback_sum_q16` 反推 K 做交叉验证（我们靠这招确认了板上真是 400/550）。

**C4. "0A9 数据"其实是 DIAG185**
同学发的 10 个窗口是 2 s 环形缓冲、固件 ID 4A575185；通过 `pend_angle_term_V/θ` 反推出
KQ_2=4690 才确认不是 0A9。
→ **教训**：拿到数据先验 firmware_id 和 K，再谈结论。

## D. 机械（最大的单项收益，但被我们低估到最后）

**D1. 桌面不平 + 螺丝松**
起摆成功率忽高忽低、"好侧/坏侧"表现分裂，折腾一周的控制参数，根因是机械。
垫平 + 复紧后起摆成功率直接到 ~100%。
→ **教训**：**先机械后控制**；每次上板前测桌面水平、紧固螺丝。

**D2. 电位器零点偏差 2.8°**
θ 均值恒为负、旋臂偏 20–27°，其实是零点偏差经 KQ_2/KQ_0=8.72 放大。
→ **教训**：稳态 θ 均值不为零一定是零点问题（稳态摆杆必须垂直）。

**D3. 电位器零点随臂角正弦变化 ±3°**
`raw_vert = 3072.83 − 5.68cos(a) − 38.63sin(a)`，一圈一次。
这是"两边不一样"的另一个来源，也是"每个版本最佳零点不同"的原因。
→ 修不了（机械偏心），只能按臂角查表或接受。

**D4. 起动阈值 274‰**
1908 次黏滑事件统计：起动前 50 ms 的 duty 峰值中位 274‰，10%/90% 分位 143/408‰。
臂静止时间占 68–90%。满量程 500‰ 只有 1.9 倍余量。
→ 这是所有摆幅问题的物理源头。

## E. 控制方案（每条都有实测否决，避免重走）

| 方案 | 结果 |
|---|---|
| KQ_0 加倍 | 阻尼 0.57→0.31，摆幅反而变大 |
| KQ_0 取负（"符号反了"） | 模型 \|z\|=1.05 不稳、发散；实机是"位置项被摩擦挡住"不是推反 |
| KQ_1/KQ_3 增大 | 臂摆 13–16° 但抖动 305‰（交换，不是改进） |
| 分状态增益 | 切换的指令阶跃本身灌 10–25 Hz 能量 |
| 位置积分 | 饱和 → 助推漂移 → 跌倒 |
| 位置低通 10 Hz | 相位越界 → 跌倒 |
| 位置低通 20 Hz | 衰减不足 → 无效 |
| 持续释放 300‰ | 摆幅 44°、滑脱 5 次 |
| 单脉冲释放 | 门限要么不触发、要么驻留条件不满足 |
| 扇区零点补偿 | 全天候生效 → 起摆失败；只平衡生效 → 震动加剧 |
| 臂速死区 | 慢摆翻倍 |
| 宽陷波 | 10–25 Hz 腰斩但慢摆翻倍 |

**核心结论：摆幅与震动是同一个旋钮的两端。** 085 安静（duty10–25 93‰）但臂摆 29.5°、
臂偏 22.8°；0E2 臂摆 13–16° 但 305‰。没有中间地带。

## F. 工程/工具链

**F1. 时序边缘不设防**
SETUP 只剩 0.023 ns 的版本"压根不摆"；c_output 的 |mv|/12 乘法必须打拍；
c_sensor 的窗口差分、c_control 的捕获门/pos_target/安全比较器都要寄存一拍。
→ **教训**：**SETUP <0.3 ns 不发版**；每次加逻辑先看 timing_paths。

**F2. 中文路径报 SP0002**
必须把 rtl 复制到纯 ASCII 路径再编译。

**F3. 固件 ID 与 host 白名单**
host 5 个 .m 的白名单忘改至少 4 次；还差点写出 9 位十六进制 ID（非法）。
→ **教训**：一版一目录、目录名=ID、编译前 grep 白名单。

**F4. 数据落点**
成功的长跑数据有时落在 capture 父目录，`run_00x` 是空的。

**F5. 运行时改 up12 在硬件上变成 0**
0B5 的 `up12_trim` 在 iverilog 里正常，硬件上等效为 0（θ 被读成 raw12×0.0801），全场 fault 5。
→ **教训**：**不要动 up12 的运行时路径**；要改就用 SW1 校准（已验证的路径）。

**F6. 取消启动姿态门**
0B6 把"既非直立也非悬垂"从 fault 5 改成直接进起摆 → 能量泵从中间角度起步只是原地抖。

---

## G. 一句话总结

> **先机械（水平/紧固/零点）→ 再验证模型与 RTL 同构 → 每版一个变量 → 每版至少两跑 →
> 发版前看 SETUP → 拿数据先验 ID 和口径。**
> 控制侧的天花板由摩擦决定，不是由参数决定的。
